# Peepl

A private, personal "people log": remember everyone you meet, where you met them, and their story. This repo is a clickable prototype of the PRD's **people list**, **mindmap**, capture flow and person profile. (A map screen existed and was removed at the user's request.) Everything is private to the user; no social features.

**Keep this file up to date.** Whenever a design decision is made or changed, a feature is added, or a next step is finished, update the relevant section here in the same change, so work can continue on any device.

## Running it

- `npm install` once, then `npm run dev` → http://localhost:5173
- **On a phone** (same Wi-Fi as the Mac): `npm run dev -- --host 0.0.0.0 --port 5174 --strictPort` (also `peepl-phone` in `.claude/launch.json`), then open the "Network" address it prints, e.g. `http://<Mac's IP>:5174`. The normal dev server stays local-only (`host: '127.0.0.1'` in `vite.config.ts`). Some office / school Wi-Fi blocks phone-to-laptop connections.
- Check before committing: `npx tsc -b && npx eslint src`
- Stack: React 19 + TypeScript + Vite, plain CSS in `src/index.css`. Data lives in the browser (IndexedDB, see Layout); sample people live in code.

If IndexedDB is unavailable it falls back to localStorage.
- **Voice is real now** (`src/lib/speech.ts`): the Composer's mic uses the browser's speech recognition (Chrome / Edge / Safari; continuous, interim words, auto-restart after pauses). Where that is missing or can't reach Google's service (Brave, Firefox: "network" error; the user is on Brave), it records the mic and transcribes it locally with Whisper (`Xenova/whisper-base.en` (user's call 2026-10-21, for accuracy; q8 ~80 MB on WASM, larger on WebGPU), downloaded once): **word by word while you talk** with Vosk (`src/lib/live.ts`, `vosk-browser`, `vosk-model-small-en-us-0.15` ~40 MB fetched once from the vosk-browser project's GitHub Pages host and cached; its own worker thread): the raw 16 kHz audio (ScriptProcessor in `recordLocal`) is fed to it and each word appears about 0.1-0.2 s after it is said, lowercase and unpunctuated and weak on names; when you Stop, Whisper redoes the whole recording ("Turning your voice into text…", 30 s chunks) and replaces the draft with accurate, punctuated text. Brave (`'brave' in navigator`) skips the browser's own speech API altogether, since it has it but blocks the Google service behind it. **The models are loaded when the app opens** (user's call 2026-10-20: "assume the user will use voice"): `preloadModels()` (`src/lib/preload.ts`, called from `Prototype.tsx` on mount, right after the first render; user's call 2026-10-21: ready by the time the mic is tapped) starts search embedding, the Vosk live-words model and Whisper all at once, and Whisper also runs 1 s of silence to compile its WebGPU shaders; browsers with their own speech service (`usesLocalVoice` false: Chrome / Edge / Safari) skip the two voice models. The Vosk tarball is kept in Cache Storage (`peepl-models`) and fed to Vosk as a blob URL, so it is downloaded once and never again (verified: second load makes no network request, ~3 s to start it). The Vosk model downloads first (a hint "Getting the voice model ready…" shows in the composer until the first words, `onLoading`), and Whisper downloads beside it; audio spoken while Vosk loads is queued and appears as soon as it is ready. Only if Vosk can't load (offline) do 0.5 s Whisper passes over the recording so far fill in instead (segments of 25 s); silence is skipped because Whisper invents words for it. The scripted demo remains only where there is no mic API at all (an http page on a phone); a blocked mic drops back to typing with a message. Chrome's built-in route sends audio to Google, so only the Whisper route is fully offline. **With an OpenAI key, the final text after Stop comes from `gpt-4o-mini-transcribe`** (user's call 2026-10-21: "use this transcription instead"): `speech.ts` packs the 16 kHz recording as a WAV (`toWav`, `src/lib/ai.ts`) and POSTs it to `/api/ai/transcribe` (`server/ai.ts`; model override `OPENAI_TRANSCRIBE_MODEL`), with up to 60 people's names (newest first) as a spelling hint; local Whisper is the fallback (no key, offline, error), and the live Vosk words and the 0.5 s stand-in Whisper passes stay local so nothing is billed per tick. Tested with text-to-speech clips: every person's name came out right ("Saoirse Gallagher"), invented company names don't (that's what the name-fix outlines are for), ~1 s for 11 s of audio, cost about a third of a cent per minute (check OpenAI's pricing). **Live words from OpenAI too** (user's call 2026-10-21: "accurate and fast"): while recording, `startAiLive` (`src/lib/ai.ts`) streams the mic (resampled 16 -> 24 kHz PCM, `pcm24`) over a WebSocket straight to OpenAI's Realtime transcription with model **`gpt-live-transcribe`** (override `OPENAI_LIVE_MODEL`); the dev server's `/api/ai/live` mints a short-lived session key so the real key stays on the server. Words appear about 1 s behind the speaker (tested in the browser with a paced text-to-speech clip: first word at 1.1 s, 40 updates over 11 s), and **replace the local Vosk words once the first one arrives** (Vosk still shows first and is the fallback with no key / offline, `aiHeard` in `recordLocal`). It was chosen by measurement: `gpt-4o-mini-transcribe` and `gpt-transcribe` also stream but only per sentence (first words at ~5.6 s of an 11 s clip), `gpt-realtime-whisper` is as fast as live but also takes no names hint. `gpt-live-transcribe` takes no names hint and no turn detection, so it can mishear a plain word ("Matt" for "Met") and the last second or so of speech hasn't arrived yet when you tap Stop; the final pass above fixes both. Streaming is billed on top of the final upload (price not checked: see OpenAI's pricing page). Only the Brave / Firefox recording route uses it; Chrome / Edge / Safari still use the browser's own recognizer (which sends audio to Google). Whisper still preloads at startup as the offline fallback; skip that when a key is set if the ~80 MB download matters. The audio leaves the device when a key is set. Misheard names go through the existing name-fix flow. Real voice notes are parsed like typed ones (only the scripted demo note, recognised by "battery recycling", gets the made-up Jordan story and tags in `draftToPerson`).
- **Models run in a background worker** (`src/lib/ml.worker.ts`, called through `src/lib/ml.ts`: `embedTexts`, `transcribeAudio`, `preload`; `worker: { format: 'es' }` in `vite.config.ts`). Embedding ~700 moment sentences and transcribing speech used to run on the page's own thread and froze typing and taps for seconds when Find opened (user's report 2026-10-20: "can't search and type on this screen"); in the worker the page stalls at most ~0.2 s. Never import `@huggingface/transformers` outside the worker. **Whisper runs on WebGPU when the browser has it** (`'gpu' in navigator`; fp32 encoder + q4 decoder, a larger one-time download than the q8 WASM build), falling back to the q8 WASM build if loading fails or there's no WebGPU (user's call 2026-10-21: faster transcription). Untested by ear so far; if it errors on first run, the fallback doesn't cover that yet.
- **AI (optional; user's call 2026-10-21: they have an OpenAI key, no Anthropic key)**: one dev-server endpoint, **`POST /api/ai/<task>`** (`server/ai.ts`, plugged in by `vite.config.ts`), holds `OPENAI_API_KEY` and the prompts; the browser side is `src/lib/ai.ts`. **Model: `gpt-4.1-mini`** (override with `OPENAI_MODEL` in `.env.local`): benchmarked 2026-10-21 against gpt-4o-mini, gpt-4.1-nano, gpt-5.4-mini and gpt-5.4-nano on messy notes, all read them equally well except nano (missed a field); 4.1-mini was the fastest (~0.8 s, no reasoning step) and cheap (roughly $0.0003 per note; check OpenAI's pricing page). Five tasks, each with the old behaviour as the fallback (**`transcribe`** and **`live`** are described under Voice): **`parse`** (Add: `refine()` in `llmParse.ts` runs while the "Creating a new profile…" card shimmers, result goes in `refined`, `parsePerson` prefers it over the regex; name / company / from / lives must appear in the note), (the prompt puts each fact in only one field, and `dedupeTodos` in `capture.ts` drops a follow-up / goal / interest that says the same thing, so a profile's to-dos never repeat; user's report 2026-10-21: "catch up and grab coffee" appeared twice; an AI interest is stored as "Loves …" like the regex's) **`rank`** (Find: `AskScreen` runs `rankWithAi()` after `findPeople()`; it sends up to 12 candidates, the rule matches' near misses plus the closest by meaning, as profile facts (job, city, tags, a clipped story and recent moments, never names or ids) and the AI says which fit **every** part of the question and why; people the rules matched exactly always stay; AI matches get a "Draft a message" button), **`draft`** (`draftMessage()`: tapping a result's action writes the text from what you know about them, `Action.goal` says what it should ask; the template `Action.draft` or a plain hello is the fallback). **Setup:** `OPENAI_API_KEY=...` in `.env.local` (git-ignored by `.env*`; read on the server only, never in the browser bundle), restart `npm run dev`. **Without a key** the endpoint answers 503, `ai()` remembers that and stops asking, and everything runs on the regex, rules + meaning search and templates (`tests/ai.test.ts`). **Privacy:** with a key set, Add notes, search questions with candidate profile facts, and draft requests go to OpenAI; voice, embeddings and the rest stay local. Dev-server only; a deployed build needs the same handlers as a serverless function. A local Qwen2.5 (0.5B / 1.5B) was tried first and removed (no reliable JSON, slow). The regex was also improved (`tests/parse.test.ts`): names / where you met after "bumped into", "ran into", "with my cousin", "named"; "grew up in / born in" (from), "now in / moved to" (lives); "super into / obsessed with" (interest); company after more roles; accented names and titles.
- **Never hang on a slow first search** (user's report 2026-10-20: a house-party query "loaded forever"): the first search has to embed every moment sentence (~700, about 20 s on a warm machine, longer on a first run). `embed()` runs one request at a time (a search asked during the warm-up waits for it instead of repeating it) and tracks progress (`searchProgress()`). `AskScreen` waits `SLOW_MS` 4 s for the meaning search; after that it shows what the rules found (or nothing) with **"Still reading your moments so I can search by meaning (38%)…"** (`Reading`, `slow: true` on the result) and swaps in the full answer when it is ready. `ml.ts` also rejects every waiting call and restarts the worker if the worker dies or fails to start (`onerror`), so nothing can wait forever. Idea if it is still slow: ship precomputed vectors for the sample people.
- **No results** (user's call 2026-10-20: "what if nobody does portraits?"): when nothing clears the cutoffs the Find screen says "No one matches “…” yet. None of the N people in your list fit, so I won't guess.", shows up to 2 people as **Closest, but not quite** (score ≥ `NEAR_SCORE` 0.3, `near` on the result) and an **Add someone new** button. The question is cut down to its topic before embedding (`topic()` in `semantic.ts`: "someone who does my taxes" -> "taxes", using `filler` from `ask.ts`) so the way people phrase a question doesn't make every job title look close. `CLOSE_TO_BEST` is 0.1.
- **Search by meaning** (`src/lib/semantic.ts`): `interpret()` runs first (rules for add / moment / catch-up / buddy / trip / intro / keyword filters); for a plain "find people like this" (`generic: true` on its result, or nothing found) `AskScreen` calls `findPeople()`, which lists the rule matches first and adds the closest people by meaning after them (skipped when the rules already found 5+; special answers like climbing buddy / trip / intro / catch-up are left as they are). There is no fake delay any more: the answer shows when the search is done, held only `MIN_THINK_MS` 450 so a fast one doesn't flash. **Results come from real moments** (user's call 2026-10-20): both the keyword rules (`inMoments` in `ask.ts`) and the meaning search read every sentence of every logged moment, including the first-meeting voice note, and a result's reason is that sentence with its moment and date ("…the pickleball courts in Prospect Park (Met at Pickleball league, Apr 2026)"); the profile (tag / job / story sentence) is only the fallback reason, and moment sentences get a +0.04 bonus in the meaning search. Rule matches are ordered by closeness in meaning. `semanticSearch()`: a local embedding model (`@huggingface/transformers`, all-MiniLM-L6-v2 q8, ~25 MB downloaded once from Hugging Face and cached by the browser, so first use needs internet) embeds each person's chunks (job, story sentences, tags, moments, to-dos). A person scores as their best chunk (cosine), which is also the "why"; `MIN_SCORE` 0.35 and within 0.15 of the best score, max 10. Vectors are cached in IndexedDB; Find warms them up on open. No LLM. Swap-in points for a real model are still parsing notes (`parsePerson`) and drafting messages.
- `src/lib/capture.ts` — the voice script text, typed-note parsing (`parsePerson`, `parseMoment`), `momentCandidates` (does a note read as a moment with someone you know?) and how a capture becomes a `Person` or `Moment`. Capture, Ask and profiles open as full-screen **layers** above the tabs (`layers` in `Prototype.tsx`; back / close pops the top one).

## Design decisions (agreed with the user)

**Visual style** (from the user's reference images: soft, clean, modern, light, pastel)
- Base is black and white: white background, near-black text (`--ink: #111113`), grey secondary text. Light and semibold weights are mixed for headlines (e.g. "Mindmap is **coming soon**").
- **Fonts:** Geist for everything (`--font-body`, and `--font-heading` for headings with `--heading-tracking: -0.04em`), Geist Mono for meta (`--font-mono`), set in `:root` and loaded from Google Fonts in `index.html`. **The serif (Instrument Serif) was dropped at the user's request**; heading sizes were scaled to ~82% when it went. Any new heading should use `var(--font-heading)` and `letter-spacing: var(--heading-tracking)`.
- **Behind the mindmap and list: the Figma "Aura" from "Disc study · Default"** (node `317:13603`; user's call 2026-10-20): four big blurred color orbs (pink `#D6347F` top left, yellow `#E8C22E` right, a blue `#2F4FD0` ellipse on the left, orange `#EC5A32` bottom right; Figma blur stdDeviation 150 = CSS blur 150px) on the light grey ground (`#f5f5f5` at 80% over ground-300 `#ccc` = `#ededed`), with the light Figma **Texture/Grain** on the ground **under** the orbs (`.aura-bg::before`, `--noise`, the same grain as the Add / Find auras, see below; on top it washed the colors out, in the Figma the auras stay smooth; user's call 2026-10-20, from "Disc study · Grouped by context" node `317:13760`, replacing the Figma's dark grain from the default frame). Data in `src/lib/aura.ts`; the list shows them still (`components/AuraBackground.tsx`), and the mindmap draws its own copy (`.mm-aura`) so the orbs can move (see Group by). **The list's still aura is a bit lighter than the mindmap's** (user's call 2026-10-20, from the Figma Connections frame `342:5841`): `.aura-bg--light` sits on ground-100 `#f4f4f4` (vs the mindmap's `#ededed`) with orbs 80% their color mixed with `#f4f4f4`. **The grain looks the same on both screens** (user's call 2026-10-20): orbs are lightened by **mixing their color toward the ground, never by opacity**, because the grain sits under the orbs and see-through orbs let it show, which looked like the grain fading in on the list. **The still `AuraBackground` is always mounted** (no longer only off the mindmap) as a base layer, so switching tabs **crossfades** instead of hard-cutting: the mindmap's own opaque `.mm-aura` fades in/out over it (`.screen` `screen-in`, now a gentle 0.5s ease). **When a filter is on, the mindmap's grouped auras carry over into the Connections list** (user's call 2026-10-20, "version 2"): leaving the mindmap for the list with `groupBy !== 'none'`, the mindmap **stays mounted** (stable `key="map"`, rendered before the list so it paints behind) as the list's background in **`asBackground`** mode — the grouped colored orbs keep their exact positions while the discs, labels and links fade out (`.mindmap-screen.as-bg .mm-world` → opacity 0, 0.4s), and the carried-over auras are **30% lighter** (their color mixed 70% with `#f4f4f4`, set on the orb's `background` in `MindmapScreen`, easing over 0.4s via `.mm-aura-orb`'s transition; still fully opaque so the grain stays the same; ground set to the list's lighter `#f4f4f4`). **With no filter** (`groupBy === 'none'`) the mindmap isn't mounted on the list, so it simply uncovers the already-present lighter still aura (the "lighten by 30%" look, as before). **Coming back from the list doesn't replay the mindmap's fade-in** (user's report 2026-10-20: going Connections → Mindmap with a filter on flashed the full still aura for a moment, because removing `.as-bg` re-applied the `screen-in` fade from transparent): once the mindmap has faded in, or has been the list's background, it gets `.is-settled` (`animation: none`; `settled` state in `MindmapScreen`), so only `.mm-world` fades back in. This replaced a short-lived exit animation that eased the orbs back home instead (`RELEASE_MS` / `.is-exiting`, removed). This replaced the WebGPU "Lavender veil" mesh (its shader files and `MeshBackground` were removed), earlier meshes, and before that the dot grid. The `--dots` grid variable is gone. The pastel auras still appear only in the Add / Ask flows (`.flow-aura`) and behind profiles (`.profile-aura`). **They drift** (user's call 2026-10-19; the first, very slow version was too subtle to notice, so it's now faster and wider): each of the four color orbs wanders up to ~45% of the screen on its own 14–25s eased back-and-forth loop (`aura-drift-1…4`, offsets as registered `--drift-*` properties so the masked grain moves with them); off for reduced motion. These carry the Figma **Texture/Grain** noise (`--noise`: fractal noise at frequency 1.25 / 3 octaves, thresholded so about half the pixels are white at 80%), masked to the pastel orbs as in the Figma (`.flow-aura::after`, user's call 2026-10-19). The profile hero keeps its own subtler `--grain`.
- Glassmorphism uses **two looks** (both frosted translucent white: `backdrop-filter` blur, white edge, soft lavender-tinted shadow). **Every white card and button** (user's call 2026-10-19: top controls, Filters menu, Connections rows, the mindmap pill and group names, ask bar, add button, the filter pill above the bar, composer, Find example cards, result cards and actions, profile cards / to-dos / Where tiles / moments, tags, white round and ghost buttons) uses the **Figma liquid glass** (Nav pill, node `248:2181`; user's call 2026-10-19, replacing the pasted glass-card CSS and a short-lived liquid-glass-js port): a 60% white fill, no border or shadow, over Figma's *Glass* effect (refraction 0.8, depth 20, dispersion 0.5, frost 0) rebuilt as an SVG `backdrop-filter` by `useGlassEverywhere` in `src/lib/glass.ts` (run on `.phone` in `Prototype.tsx`; it finds everything matching `GLASS_SELECTOR`, including elements added later, and the CSS rule at the end of `index.css` lists the same selectors; the **ask bar and add-person button use an 80% white fill**, and **every text box (the Composer, and the ask bar) is 80% with Figma frost 12** (user's calls); the top controls, Filters menu and Connections rows are back at the standard 60% (they were 40% only with the darker mesh), and the **Filters menu adds Figma frost 12** (`--glass-frost: 12`, a blur of the backdrop before it's bent, stdDeviation 6); the **profile's back and ⋯ buttons** are glass too but keep their 14% white fill (`--on-dark-glass`); anything inside another glass card is **not** glass and keeps its own style, user's call: e.g. the summary card's tags and a result's white **Draft a message** pill; the CSS rule uses `:not(:is(…) *)` for this) (a displacement map shaped like the element bends the background within 20px of the edge; R / G / B bent by slightly different amounts), plus its light (−45°, 0.8) as an inset rim, bright top-left and faint bottom-right. SVG backdrop filters only work in Chromium (Chrome / Edge); elsewhere they show just the fill and rim. The **ask bar and composer** use the "Frost" look (`--glass*`: blur 34 / saturate 150 / fill 0.78, strong fill 1.0, edge 0.92), picked in the old style panel and now fixed in `:root`. The **other glass items** — list cards, find results and profile sheet — use the `--glass-vivid*` set. **No beige anywhere** (user's call 2026-10-19): every screen, the profile, the flow base and the desktop backdrop use off-white `--bg` (`#f4f4f4`). The old cream `#f4efe7` and `--ground-200` beige `#e9e1d5` are gone. The "soft" round and pill buttons use the Figma light gray `--pressed` instead.
- **Avatars: circles with the Figma "Blob club" characters** (user's calls 2026-10-19).
