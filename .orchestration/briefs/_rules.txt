## iOS builder rules (verbatim, apply to every brief)
- Run `xcodegen generate` (in ios/) after adding or removing files.
- Use a worktree-local `-derivedDataPath build` (i.e. ios/build), so builds do not collide.
- The acceptance check is `xcodebuild test` against a named simulator: `-destination 'platform=iOS Simulator,name=iPhone 18 Pro'`. Do not drive the shared Simulator UI; only the manager takes screenshots, one at a time.
- Never commit `ios/build` or `ios/Peepl.xcodeproj`, never commit anything, and never commit secrets (the `.env.local` key stays on the server).
- Touch only the files listed in the brief; if more files must change, stop and report.

## Also
- The TypeScript in src/ and tests/ is the spec; port behavior and tests, not structure.
- iOS 26+, SwiftUI + SwiftData, Swift language mode 5, system font (Geist comes in M5), native `.glassEffect` via Theme.swift's `.glass()`.
- The core <-> UI contract is `.orchestration/briefs/M1-interface.md`. Match its signatures exactly.
- Test command (from ios/): `xcodegen generate && xcodebuild test -project Peepl.xcodeproj -scheme Peepl -destination 'platform=iOS Simulator,name=iPhone 18 Pro' -derivedDataPath build 2>&1 | tail -40`
- Write your report to `.orchestration/reports/<task-id>.md` in this format: files changed, acceptance check result (test count, pass/fail), anything surprising. Keep it short.
- Smallest complete change; no extra features. Read CLAUDE.md sections you need, not all of it.
