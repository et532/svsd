Goal: Back up and Restore that are safe: share-sheet export, validated restore with Merge / Replace.
Files you may touch: ios/Peepl/Services/Backup.swift, ios/Peepl/Screens/SettingsView.swift, ios/Peepl/ConnectionsView.swift (only the EmptyPeople button), ios/PeeplTests/BackupTests.swift (new).
Do not touch: AIClient, Nudges.swift, Logic/LocalAI.swift, Models.swift (no schema change), anything else.
Spec:
- Format: keep `version` (current 1, add `static let currentVersion`), add `exportedAt` (ISO8601) and `counts` (people, moments) as OPTIONAL fields so old files still decode. Newer version than known: refuse with a clear message ("This backup was made by a newer version of Peepl. Update the app to restore it."). Still includes name fixes. AI / consent settings and nudge snoozes are not exported.
- Export: build the file, write it to a temp file named `Peepl backup YYYY-MM-DD.json` (local day), re-read and decode it to verify, then present via a share sheet (ShareLink or UIActivityViewController; Mail, AirDrop, Files). Replace the fileExporter. On failure nav.say a clear message and share nothing.
- Restore: fileImporter -> read data -> decode + validate the WHOLE file (version, ids non-empty and unique, to-do/moment ids unique) BEFORE touching data. Then a confirmation sheet/dialog: "File has N people, this phone has M" with Merge (default, prominent) and Replace everything (destructive style) and Cancel. Merge: by person id; new ids are added; on a clash keep the one with the newer lastContacted, tie-break more moments, otherwise keep the phone's; never delete anyone; a kept person may gain moments/todos missing by id from the other (optional; if you do it, test it). Name fixes: merge the dictionaries (file wins only for missing keys when merging; replace wins entirely on Replace). Everything applied in one pass with a single save; if anything throws before the save, call context.rollback() so a bad file changes nothing. Result toast: "Restored X people" / "Merged: X added, Y updated".
- The existing `BackupFile.restore(into:)` is replaced by `restore(into:, mode:)` returning a result; update all call sites (grep).
- EmptyPeople (ConnectionsView): add a third button "Restore from a backup file" that opens the same import flow (put the shared flow in a small reusable view modifier or view in Backup.swift / SettingsView.swift so both entry points use one implementation).
- Tests (BackupTests, in-memory ModelContainer as other tests do): round trip export -> wipe -> restore equals original incl. to-do order, mutual notes, moments, name fixes; merge keeps both sets and never deletes; merge clash picks newer lastContacted; Replace removes people not in the file; corrupt JSON throws/returns error and the store is unchanged; newer version refused and store unchanged; duplicate ids in file rejected before any change; old file without exportedAt/counts decodes; 500-person file restores in under 5 s.
Acceptance: `cd ios && xcodegen generate && xcodebuild test -project Peepl.xcodeproj -scheme Peepl -destination 'platform=iOS Simulator,name=Peepl-MVP1' -derivedDataPath build 2>&1 | tail -40`: all tests pass. Report counts. Commit listed files on the branch only.
Validator should also check: restore cannot partially apply; no network used; Backup works with PeopleStore.delete semantics (links cleaned on Replace).
